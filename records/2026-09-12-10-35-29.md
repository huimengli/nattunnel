# 会话记录 — 2026-09-12 10:35

## 本次需求(用户原话/现象)

用户运行 exe 报 `ModuleNotFoundError: No module named 'cryptography'`(nattunnel_client.py line 43)。

## 根因与修复

1. **requirements 缺包**: `client/requirements.txt` 原来只有 websockets, 而客户端 import cryptography
   (RSA 令牌握手)。build.bat 每次在**全新 client/.venv** 里 pip install -r requirements.txt,
   所以 cryptography 从未打进新构建; 之前能跑的 exe 是直接用开发 venv(碰巧装了 cryptography)构建的。
   **修复**: requirements.txt 加 `cryptography>=41`。
2. **顺手发现的混部握手缺陷**(用假令牌实测暴露): 客户端 REST 调用 `/api/me`、`/api/tunnels/{tid}`
   是绝对路径 — 混部 nginx 只路由 `/tunnel/` 与 `/nattunnel-admin/`, `/api/*` 落进网盘站 → 404,
   **LAN 客户端在混部下永远无法握手**(独占域名部署无此问题)。
   **修复**: 客户端新增 `API_BASES = ("/api", "/nattunnel-admin/api")` + `api_json()` —
   404/405 时自动换前缀重试, 401 等业务码直接抛出; verify_token/tunnel_config 改走 api_json。
   无需客户端配置、服务端零改动(管理端前缀就是 API 入口)。
