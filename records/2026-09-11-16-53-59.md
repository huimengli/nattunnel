## 增强实现: /tunnel/{tid} 纯 HTTP 直转

- **`server/app/http_bridge.py`(新增)**: `HttpBridgeMiddleware` ASGI 中间件
  - 仅拦截 scope.type=http 且无 `Upgrade: websocket` 的请求(WS 握手原样放行给中继);
  - 匹配 `^/tunnel/([A-Za-z0-9]{8})(/.*)?$`, 子路径整体透传给本地服务;
  - 仅 tcp 隧道支持(udp → 400); 无 LAN 在线 → 503 JSON; 未找到/停用 → 404(不泄露存在性);
  - 每个 HTTP 请求 = 一条独立隧道流: 分配 pid、注册**队列式伪公网入口**(LAN 中继循环把响应帧投进队列),
    T_NEW/T_DATA 直发 LAN(websockets v17 的 `send_in_progress` 机制保证多路并发 send 安全);
  - 请求头剔除 hop-by-hop/WS 握手头, Host 重写为 `127.0.0.1:<local_port>`, 强制 `Connection: close`;
  - `_RespParser` 增量解析响应: 状态行/头 → ASGI `http.response.start`, 随后流式回传;
    结束判定 = Content-Length / chunked 终结符(`0\r\n\r\n` 尾部扫描) / T_FIN; 头等待限时 20s(504), LAN 掉线(502/中断)。
- **`server/app/main.py`**: 注册中间件; LAN 侧中继循环**补转发 T_FIN**(此前被忽略, 公网流无法得知目标关闭)。
- **`server/nginx/nattunnel.conf`**: `map $http_upgrade $connection_upgrade`, `/tunnel/` 改
  `proxy_set_header Connection $connection_upgrade` — 普通 HTTP 不再被强推 `Connection: upgrade`(服务端仍容错处理)。

## 踩坑(本轮修复的两个 bug)

1. `'Tunnel' object has no attribute 'local_target_host'`: 本地目标 host 只在客户端 config,
   服务端隧道模型无此字段 → Host 头改用固定 `127.0.0.1:<port>`。
2. `_send_lan` 空 payload 时 `range(0,0,...)` 不发帧 → **T_NEW 被静默丢弃**, 客户端未建流, 请求帧成孤儿 →
   表现为 504/超时。修复: 空 payload 也发一帧。

## 使用方式变化

- 浏览器直接打开 `http(s)://公网域名/tunnel/<短链>[/子路径]` 即可访问内网 Web 服务(tcp 隧道);
- WS 客户端用法不变; udp 隧道仍仅 WS。
- nginx 部署后普通 HTTP 与 WS 共用同一 location(map 头已处理)。
