# 2026-11-04 20:17-27 管理页"编辑隧道"保存失败(tunnel id already exists)

- 状态: 完成(本地 commit, 未 push)
- 关联: 上一需求 records/2026-11-04-19-06-38.md(header_timeout_s); **本 bug 早于该改动**

## 现象(用户截图 + 报告)

- 管理页"编辑隧道 smGvs9xQ": 目标主机 127.0.0.1, 端口 8080, 响应超时(s) 300, 点"保存" → 右下角 toast **"tunnel id already exists"**。
- 用户: "修改 tunnel 配置失败, 无论 tunnel 是否启动都失败" — 与在线状态无关(服务端根本没收到 PATCH)。

## 根因

`server/app/static/index.html` 的 `saveTunnel()` 用"查表命中"判定编辑/新建:

1. `const tid = ...value.trim().toUpperCase()` — 把短链 ID **强制大写**;
2. `state.tunnels.findIndex(x => x.tunnel_id === tid)` — 生成 ID 是**大小写混合**的
   (`routers/tunnels.py:20` `ALPHABET = "ABCDEFGHJKLMNPQRSTUVWXYZabcdefghjkmnpqrstuvwxyz23456789"`),
   `smGvs9xQ` ≠ `SMGVS9XQ` → idx = -1;
3. 于是走 **POST** `/api/tunnels` 并带 `tunnel_id: "SMGVS9XQ"`;
4. MySQL 默认 Collation 大小写不敏感 → `create_tunnel` 的存在性检查命中 `smGvs9xQ` →
   `HTTPException(409, "tunnel id already exists")` → toast 原样显示英文 detail。

副产影响(改动前): 新建隧道手填混合大小写 ID 会被静默大写(填 `abHjkmn2` → 实际建 `ABHJKMN2`),
与 `schemas` 的 `pattern=r"^[A-Za-z0-9]{8}$"`(接受小写)和生成 ID 风格不一致。

## 修复(仅前端 index.html)

- `openTunnelModal(tid)`: 记录 `editingTid = tid || null`; 编辑态 `#tm-tid` 设 `readOnly`(改 ID 需新建);
- `saveTunnel()`: 编辑/新建判定改用 `editingTid`(不再大写化查表); 编辑态 ID 被改写 → toast
  "隧道 ID 不可修改(改 ID 请新建隧道)" 且不发请求; 新建态正则放宽为 `^[A-Za-z0-9]{8}$`(与服务端一致),
  手填 ID 原样保留; PATCH 用存储的原 ID(大小写不变)。
