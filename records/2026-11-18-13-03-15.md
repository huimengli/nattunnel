# 需求记录 2026-11-18-13-03-15 — Unity 标准 UDP 入口(公网 UDP 端口映射)

## 需求原文(用户, 2026-11-18 13:03)
> 现在项目的UDP不是标准的UDP端口映射,我需要给UNITY 用,你看看有没解决办法? 或者新增一个unity选项? 此次开发走分支 feature/AI_Unity

附图结论(上一轮咨询): 隧道是 `wss://host/tunnel/<ID>` + 子协议 `nattunnel-relay` 的 WebSocket 子协议型入口,
Unity Transport(NGO)的 UDP 模式连不上它, WS 模式也不支持自定义子协议头 —— 协议不匹配。

## 现状与根因(只读审查)
- 公网侧现有三种入口: 纯 HTTP 直转 / WS 握手桥接 / WS 子协议 `nattunnel-relay` 帧协议裸流(`U_DATA 0x41` 数据报)。
- 全部入口都是 **TCP 上的 WebSocket**: 没有 UDP 报文, 没有可连的 `IP:UDP端口`。
- Unity Netcode for GameObjects 的 UnityTransport 是**纯 UDP**: 只能"连到 `IP`+`端口`"的 UDP socket,
  无法自定义 WS 子协议/头(WebGL 才有 WS), 因此现有 udp 隧道对 Unity **不可用**。

## 方案(本次实现)
服务器本身有公网 IP → **由服务器把隧道暴露为标准 UDP 端点**, 公网侧不再走 WebSocket:
- 每条 `proto=udp` 隧道新增配置 `udp_port`(公网 UDP 端口)与 `udp_allow`(源 IP 白名单, 空=放行);
- 服务端在 `UDP_LISTEN_HOST:udp_port` bind UDP 套接字; **每个源地址(对端 IP:端口)= 一个 peer_id**,
  与 WS 子协议裸流共用同一房间与帧(0x41 U_DATA), LAN 侧为每个 peer 起本机临时 socket(客户端已有实现, 无需改);
- 回包用 peer 的**源地址** sendto(UDP 无连接); 空闲 60 秒回收对端; 内网侧离线丢包;
- Unity 侧**零代码改动**: `Server Address = 服务器公网IP`, `Server Port = udp_port`,
  `NetworkManager.StartServer()` 监听本地端口(隧道 `local_port`)。

不新增 `proto=unity` 取值: Unity 用的就是标准 UDP, 语义与 `udp` 完全一致;
新增取值只会造成"同一语义两个名字"(与 2026-11-03 的 http/tcp/udp 语义表冲突)。Unity 入口以
`udp` 隧道 + `udp_port` 字段 + 管理页 Unity 提示 呈现。

## 边界与风险
- UDP 入口**无鉴权**(与 WS 桥接/裸流一致): 提供 `udp_allow` 源 IP 白名单 + 建议随机高位端口; 敏感游戏/服务配防火墙。
- 必须单 worker(UDP 房间仍是进程内存态, 与中继一致)。
- 服务器需放行入站 UDP(nginx 不参与, 不反代 UDP); 混部部署同样直连 FastAPI 进程。
- Unity 的 `Server Address` 官方语义是 IPv4: 建议填服务器公网 IP(域名需先解析), 域名变化要改配置。
- 隧道带宽由客户端令牌桶执行(服务端不重复限流)。
- Unity 侧多玩家经同一 NAT: 源端口不同即为独立对端; 需客户端源端口不重复(标准实现满足)。


## 实测中的根因与修复(2026-11-18 追加)
- **`main.py` 中继 `RELAY_SUBPROTOCOL` 未定义**: 为加 `/api/udp/status` 重排 import 时删掉了
  `from .relay import (...)` 整块 → WS 建隧时 `tunnel relay error: name 'RELAY_SUBPROTOCOL' is not defined`
  + `ASGI callable returned without completing handshake`, 表现为自测 A/B/C/D/E/G 全部"客户端 lan 侧上线"失败。
  已恢复该 import 块(与 HEAD 一致)。教训: 改 import 逐行追加, 不要整块替换。
- **首包竞态(已修, 见 docs/unity-ngo.md 踩坑备忘)**: 客户端 `run_udp` 在 `U_DATA` 早于建端任务完成时丢首包;
  与 2026-11-03 TCP 路径同款竞态同法修复(等建端任务结束再投数据)。服务端 150ms 兜底睡眠已移除(不需要)。
- **自测 `udp_native` 阻塞 recv 饿死事件循环**: 回显服务与测试同进程 → 回显永不触发, 阶段 G5-G8 必失败;
  已改为非阻塞轮询(踩坑: 单进程同时跑回显 + 收包必须非阻塞)。
- 台架 `tools/unity_udp_test.py` 两个 Windows 坑: `stdin=subprocess.DEVNULL` 使 `isatty()` 为真(首启向导被触发后
  `SystemExit: 已取消`)→ 用 `stdin=subprocess.PIPE`; GBK 控制台打印中文崩溃 → 子进程 `PYTHONIOENCODING=utf-8`
  + `encoding="utf-8"` 捕获 + 父进程 `sys.stdout.reconfigure`。
