# 会话记录 — 2026-09-11 18:00

## 本次需求(用户报告)

浏览器打开 `http://127.0.0.1:8000/tunnel/xN5MYedx` 后白屏, 控制台报错:
`_app/immutable/*.js|css`、`manifest.webmanifest`、`favicon.svg` 全部
`GET http://127.0.0.1:8000/tunnel/_app/...` → 404(动态模块导入失败)。

## 诊断结论

- 页面本体 200 正常; 404 的是 **llama.cpp UI 的相对路径资源**。
- llama.cpp 的资源引用是相对路径(`_app/...`、`favicon.svg`), 浏览器基于**文档 URL 所在目录**解析:
  用户开的是不带尾斜杠的短链 `/tunnel/xN5MYedx` → 目录基点为 `/tunnel/` →
  资源请求变成 `/tunnel/_app/...`, **掉出隧道 ID 前缀**, 不匹配直转中间件, 落到静态挂载 404。
- 即使带尾斜杠也只是"碰巧"正确(`/_app/...` 解析进 `xN5MYedx` 目录), 且 JS 运行时动态 fetch
  同样依赖基点 — 需要确定性修复。

## 修复: HTML 响应注入 `<base href="/tunnel/{tid}/">`

`server/app/http_bridge.py`(_RespParser + _bridge):
- 仅对 **text/html 且无 content-encoding 且非 chunked** 的响应, 在 `<head>` 标签后注入
  `<base href="/tunnel/{tid}/">` — HTML 标准机制, 把整份文档(静态标签 + JS 运行时相对 fetch)
  的引用解析全部钉到隧道前缀内; 命中子路径规则后正常转发到本地服务。
- 响应头先于首字节发出, 故注入在**发响应头之前**完成: 等 `<head>` 出现(缓冲上限 64KB),
  同步修正 `Content-Length`(+注入长)与内部体长度(`note_injected`);
  找不到 `<head>` / 文档自带 `<base>` → 原样放行不覆盖。
- chunked 不注入: 其显式块大小会被中途插入的字节破坏帧; gzip 字节流里看不到明文 `<head>`, 同样跳过。

## 踩坑(本轮修复)

1. 首版注入后 `pop_body` 仍按**原 CL** 截断 body → 响应尾部 31 字节(恰为注入长)被静默丢弃,
   Content-Length 与实体不符。`note_injected(n)` 同步 `_remaining` 修复。
2. selftest D6 首版用大写键 `hdrs.get("Content-Length")` 取值 — uvicorn 返回小写键 → 误报 FAIL;
   改大小写不敏感遍历。

## 已知边界(文档已注明)

- gzip/chunked 的 HTML 响应不做注入(此类应用需自身支持子路径或改用 WS 客户端)。
- 绝对根路径引用(`href="/"`)与 `ws://` 相对 WebSocket 引用不在 `<base>` 覆盖范围(前者少见, 后者 v1 不支持)。
- 注入上限 64KB: `<head>` 出现在文档极深位置的应用跳过注入(极少数)。
