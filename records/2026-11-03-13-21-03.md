## 本次需求(用户原话)

"分析这个项目,然后对隧道进行优化: 1. tcp隧道实测只能转发 HTTP 但 WebSocket 握手到不了
2. 修改隧道选项: 将tcp,udp改为http,tcp,udp 现在要求将原有的tcp改为http,tcp需要支持WebSocket握手"

## 需求解读

1. 隧道协议选项由 `tcp, udp` 扩展为 `http, tcp, udp`。
2. 原 `tcp` 的语义(浏览器直开短链的纯 HTTP 直转 + HTML `<base>` 注入)迁到新的 `http` 协议;
   存量 `tcp` 隧道在首次启动时一次性迁移为 `http`(保持现有短链行为不变)。
3. 新 `tcp` = 原生 TCP 字节流隧道, 必须支持 **WebSocket 握手全通**: 浏览器(或任意 WS 客户端)
   对 `wss://域名/tunnel/<短链>[路径]` 的 WS 握手经隧道到达内网 WS 服务, 101 与后续数据帧双向透明。
4. 帧协议公网侧保留给"裸流"工具(WS 子协议 `nattunnel-relay` 声明), 与"WS 桥接"两种公网侧角色区分。

## 现状分析(根因)

- `server/app/http_bridge.py`: `HttpBridgeMiddleware` 只拦截 `scope.type == "http"` 且
  `Upgrade != websocket` 的请求 → WS 握手请求全部落到 `main.py` 的 `/tunnel/{tid}` WS 中继;
  中继把该连接当"公网侧裸流" (`T_HELLO` + 帧协议), 浏览器收到 101 后与中继对话,
  永远不会到达内网的 WS 服务 → **WS 握手到不了**(实测现象)。
- 中继的 `data_types` 按 `proto == "tcp"` 选 T_DATA, 其余(含 udp)选 U_DATA; 无 `http` 概念。
- 隧道字段 `proto` 取值 `tcp|udp` (models/schemas/管理页 select/seed 演示隧道 XgMacp2G)。

## 方案要点

- `http`: 纯 HTTP 直转(原 tcp 行为, 含 `<base>` 注入); WS 握手在 http 隧道也桥接(浏览器页面里的 WS 可用)。
- `tcp`: 原生字节流; 公网侧 WS 握手桥接 `wsproto` 客户端 ↔ 内网 WS 服务(转发握手请求、解析 101、
  双向转发数据帧/ping-pong/close); 裸流工具用子协议 `nattunnel-relay` 走中继。
- `udp`: 不变(仅 WS 裸流中继)。
- 存量迁移: `AppSetting` 记 `proto_tcp_to_http` 标记, 首启一次性把 `proto='tcp'` → `http`; 演示隧道保持 `tcp`。
- 客户端: `http`/`tcp` 均走 `run_tcp`(字节流), `udp` 走 `run_udp`; T_CONFIG 协议变更判定同步。
- 管理页 select 三项; 工具与 selftest 加 `nattunnel-relay` 子协议; 新增 WS 握手桥接测试(自测阶段 E)。
