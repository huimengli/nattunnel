## 改动明细

### 1) 配置热更新(修复"改端口不生效")

- 新帧 `0x21 T_CONFIG`(server→LAN, payload = JSON `{proto, local_port, bandwidth_kbps}`):
  - `server/app/relay.py`: 常量 + `Hub.get()`(只读查询) + `push_config_to_lan(room, ...)` 异步推送。
  - `server/app/routers/tunnels.py` `PATCH /tunnels/{tid}` 改 async:
    - **协议变更** → 原语义保留: 拆房间(客户端自动重连拉新配置);
    - **端口/带宽变更** → 不再拆房间, 直接 T_CONFIG 推给在线 LAN 侧。
- `client/nattunnel_client.py`:
  - TCP/UDP 主循环各加 `T_CONFIG` 分支 + `apply_config()`:
    - `local_port` → 更新 `live["port"]`, **新流立即用新端口**(已建立的流保持旧连接);
    - `bandwidth_kbps` → `TokenBucket.set_bandwidth()` 即时改速;
    - `proto` 变更 → 退出当前会话, 主循环重连(拉取新协议配置)。
- UDP 的 `sendto` 目标同样读 `live["port"]`, 即生效。

### 2) `-s/--server` 参数

- `client/nattunnel_client.py` `main()`: `-s/--server <http(s)://...>` 覆盖 config.json 的 server(校验 scheme, 去尾部斜杠)。
- `build.bat` 尾注同步更新用法说明。

### 3)+4) authtoken 启动认证(token-first 流程)

- 客户端**不再 RSA 登录**(删除 login() 与 cryptography 依赖, `client/requirements.txt` 只剩 websockets):
  - `-a/--auth <token>` 直接提供; 省略则启动后控制台提示粘贴(无效可反复重输; stdin 为 EOF → 退出码 2 并提示);
  - `-a` 提供的令牌无效时, 回落控制台输入而非直接退出;
  - `GET /api/me` 校验令牌(`user/role` 打印到日志) → `GET /api/tunnels/{id}` 握手拉配置 → `WS /tunnel/{id}` (Bearer) 建隧。
- `config.json` 精简: `{server, tunnel_id, local_target_host?, verify_ssl?}`(username/password 字段移除; 旧配置因只读已知键仍兼容)。`client/config.example.json` 同步。
- 401/403 时日志明确提示"到网页管理端重新获取令牌并重启客户端"(JWT 7 天)。
