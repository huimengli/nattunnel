# 会话记录 — 2026-09-11 21:17

## 本次需求(用户原话)

用户在 keliit.top 服务器部署时报错 `Access denied for user 'nattunnel'@'localhost' (using password: YES)`(run.py --port 9000, MySQL 1045),
并要求:**"启动时检测管理员账户,不存在则用控制台要求创建"**。

## 实现

### 1. 首启交互式创建管理员(`server/app/seed.py`)
- `_bootstrap_admin` 新优先级:
  1) **stdin 是 tty(交互终端)** → 控制台引导: 用户名[默认 admin, 2-32 位字母数字下划线校验] +
     密码(至少 8 位, getpass 隐藏输入, Windows 无回显环境自动退回明文 input) + 二次确认, 循环到合法;
     EOF/Ctrl+C → 干净退出("已取消管理员创建")。
  2) **非交互(systemd/docker)** → 旧行为: `.env INITIAL_ADMIN_PASSWORD` 或随机 16 位+日志一次性打印。
- 已有 admin 的库不受影响(不覆盖); 本地开发/CI 回归无变化。

### 2. `run.py` CLI 参数
- 新增 `--host` / `--port`(默认取 .env 的 HOST/PORT) — 用户的 `python run.py --port 9000` 现在生效;
  之前该参数被静默忽略(服务仍起在 8000)。

### 3. MySQL 1045 排障(文档 `docs/deploy-keliit-top.md` 新增 §9)
两种根因:
- `.env` DATABASE_URL 密码与 MySQL 实际用户密码不一致;
- **用户主机范围坑**: DSN 经 TCP 连 127.0.0.1, 需 `'nattunnel'@'127.0.0.1'` 或 `@'%'`;
  只建 `@'localhost'`(socket-only) 会拒 TCP。
文档给了一键修复 SQL(双 host 创建 + GRANT)。

### 4. 配套更新
- `.env.example`: HOST 默认 127.0.0.1; INITIAL_ADMIN_* 注释改为"仅非交互场景";
- README 快速开始: 首启终端交互流程; deploy-keliit-top.md §3/§4 重写(.env 去掉 INITIAL_ADMIN 必填,
  先手动终端跑一次创建管理员再交 systemd; --port 9000 时 systemd ExecStart 与 nginx proxy_pass 同步);
- 本地 `server/.env` 的 HOST=0.0.0.0 同步改为 127.0.0.1。
